# Round 5, turn 2 — make the cue identify the track

**Diagnosis.** Turn 1 already injects cues every frame. The checkpoint has nonzero cue-position weights; literal cue ignorance is unproven. Its global cue vector, one recurrent state and three indexed heads still permit the old left-to-right shortcut. Near-tie errors remain large, and validation NLL is still falling when the 6000-step ceiling stops training after 206.16 seconds. This supports testing stronger binding and substantially more training, without claiming to have isolated either cause.

**Change.** `BoundCueTracker` encodes each video once, then runs the same GRU/head weights for each query. Each query's own noisy position, presence, object count and wall geometry enter every recurrent step, the initial hidden state, and the head. It predicts displacement from that cue; frame-0 means equal the observed cue. No slot index, sort, or other cue's ordered coordinates enter the query. Permuting cues/presence must permute outputs at every frame. Training also permutes query/target order without changing rendered pixels. Both K=1 and K=3 models copy the identical original `hard/final` CNN/GRU/head1; both replace the old indexed position head and receive identical new cue-path initialization. Only output component count/initial symmetric mode offsets differ. This is a new shared head, not an exact warm reproduction of old predictions.

**Training.** Batch 8; 120,000 paired updates, 960,000 sampled clips per head. Warm LR for 1000 steps from 1.5e-5 to 3e-4, hold through 40k, cosine to 1.5e-5 at 120k. Keep beta-NLL and identical per-slot loss normalization; auxiliary MSE decays over 8000 steps. Run at most three 35-minute segments, stopping at cumulative 40k/80k/120k when reached, resuming the same schedule/Adam/RNG. Turn-1 throughput predicts 68.7 minutes; a 1.5× recurrent overhead would take 103 minutes. That overhead is an estimate; guards cap actual work. Save every 1000 steps; choose one **paired** best snapshot by the mean of both heads' validation NLL, with fixed half-random-peek `hard_val[256:384]`. Log visible error, near-tie counts/errors and frame-0 error. No selection on a test split.

**Baselines and data.** Retune the PF on validation only: q={.02,.15,.5,1,2}, miss={.05,.2,.35,.5,.7}, r={.3,1,3,6}, bandwidth={.5,1.5,4,8}, P=512. This includes all prior candidates and brackets the old q=.5/miss=.35 boundaries: 400 PF + 24 unchanged Kalman settings, screening 24 clips and confirming 3 finalists/method on 64 different clips. Keep measured boundary flags. Original `fresh` stays seeds 51034000+i and is preliminary; **turn2_fresh uses 52024000+i**, 512 headline clips. No turn-2 headline clip is generated in Astra's tests. Keep the old 64-clip legacy comparison secondary. Thresholds use val[128:160], cue interventions val[384:416].

**Measures/gates.** Same error, mixture NLL, Rosenblatt coverage, identity and peek-value metrics as turn 1; fixed cost/coverage remains one look for both look policies. Add runner tests for shared initial weights, all cue-path gradients, full/streaming parity and all-frame query-permutation equivariance. Probe turn-1 and turn-2 checkpoints on validation; mean-cue ablation is an OOD diagnostic, not a new baseline. Only claim improved binding if later visible accuracy and near-tie errors improve; a hard frame-0 anchor alone does not establish tracking.

**Budget and limits.** AC total guarded allocation ≤128.5 minutes, training ≤105; minimum viable AC result is the first segment's paired best. If on battery, use a separate 24k-step/22-minute run and smaller evaluation, ≤34.5 minutes total. All GPU/heavy CPU jobs use `gpu_run`, four threads, expected memory <16 GB (unmeasured for the new model). Re-run actual SIGKILL/resume smoke before >20-minute jobs. Turn 2 changes binding and training exposure together, so it cannot separate their causal effects. One training seed; sequence bootstrap CIs do not measure seed variability. All learned turn-2 outcomes are pending runner.
