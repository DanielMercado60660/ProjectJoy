# 29 · Monster Factory: GANs vs modern generative models

This project draws a labeled dataset of tiny procedural monsters. It then trains four image generators from scratch in MLX on the same 32×32 data, each under the same explicit training caps (2.5 PFLOP or 25 train-min, whichever is hit first). Only DDPM vs flow is truly compute-matched (same U-Net, both hit the FLOP cap at identical steps); the cheaper VAE and GAN hit the wall-clock cap first and used 0.8 and 1.2 PFLOP:

| model | what it is |
|---|---|
| **VAE** | conv encoder/decoder, 128-d latent, Gaussian likelihood (σ=0.15 in [-1,1] units) |
| **DCGAN** | transposed-conv generator with BatchNorm, conv discriminator with LayerNorm, non-saturating loss |
| **DDPM** | 6.5M-param U-Net (64·[1,2,2] channels, attention at 8×8), ε-prediction, 1000-step linear schedule, DDIM/ancestral samplers |
| **Flow matching** | the *same* U-Net, rectified-flow objective (x_t=(1-t)·noise+t·data, target v=data−noise), Euler/Heun samplers |
| **Conditional flow** (go-deeper) | same U-Net + 6 attribute embeddings with 15% null-token dropout for classifier-free guidance |

Two non-neural reference "generators" calibrate the metrics. **PCA-Gaussian** is a classical baseline: a Gaussian over the top 64 pixel-PCA components. **Copy-a-train-image** is a pure memorizer, and it sanity-checks the memorization detector.

All evaluation goes through an **attribute classifier**, trained once on real data, that reads the 6 attributes off any image. See RESULTS.md for numbers.

**Results at a glance.** DDPM and flow matching are exactly compute-matched: same U-Net, 4,503 steps, 2.5 PFLOP each. VAE and GAN ran under the same caps but stopped on the 25-min wall clock with less compute, so treat them as wall-matched, not FLOP-matched. Same U-Net, same compute, but **flow matching** reaches classifier-feature FD **6.2** against **13.3** for DDPM (DDIM-50), and covers 880 attribute combos against 727. With only ~8 Euler steps, flow already matches or beats DDPM's best sampler (ancestral-250): CFD 7.8 vs 8.7 in the 1,000-sample sweep, a gap about the size of seed-to-seed noise, at ~31× fewer network evaluations (8 vs 250 NFE of the same U-Net). Note 6.2/13.3 compare flow to DDPM's *weaker* DDIM sampler; against ancestral sampling the 1× gap is smaller. The DCGAN color-collapsed (near-identical brown monsters) for roughly the first half of its budget, then partly recovered (recall 0.22). With guidance, the conditional flow model draws the requested 6-attribute recipe correctly **97.9%** of the time (chance 0.08%). No model memorizes by a pixel-space nearest-neighbor test (all at or below the real-data rate). **At 2× budget** all models improve a lot (CFD): flow 1.5, DDPM 2.6, VAE 8.1, GAN 15.9. Flow still leads, but DDPM's best sampler nearly catches up. Flow's remaining edge is ~16× fewer network evaluations at similar quality.

## Dataset (`data.py`)
Six attributes give 4·6·3·2·3·3 = **1296 combos**:
- shape: blob / square / triangle / star
- color: red / orange / yellow / green / blue / purple
- eyes: 1 / 2 / 3
- horns: none / horns
- mouth: smile / fangs / open
- pattern: plain / spots / stripes

On top of these sit continuous nuisances: position, scale, rotation (±12°), color shade, background tint, blob wobble, spot placement and pupil direction. Each monster is rendered at 128 px and downsampled with Lanczos to 32 and 64 px. The fixed split (seed 0) is 40,000 train and 8,000 test images, stored in `data/monsters.npz`, which is about 190 MB and is regenerated by the command below.

## How to run (exact commands, from this folder)
```bash
../.venv/bin/python data.py --grid          # dataset (~15 s, 4 CPU workers) -> data/monsters.npz + media/real_grid_*.png
./smoke.sh                                  # tiny end-to-end check incl. checkpoint resume (~1.5 min, temp dir)

# Everything GPU-heavy runs through a work queue: each queue.sh loop grabs one shared GPU slot via ../bin/gpu_run,
# then session.py works through the pending tasks in that slot for <=42 min (training tasks resume from runs/<x>/latest).
# Tasks (see TASKS in session.py): classifier -> flow, ddpm, gan, vae -> eval_main -> flow_cond -> sweep, stability,
# cond eval -> (go-deeper) *_x2 continuations + eval_x2. Two loops ran in parallel:
nohup ./queue.sh > logs/queue_1.log 2>&1 &
nohup ./queue.sh > logs/queue_2.log 2>&1 &

# The same steps by hand (what session.py runs):
../bin/gpu_run ../.venv/bin/python train_classifier.py                       # 20 epochs
../bin/gpu_run ../.venv/bin/python train_gen.py --model flow --run runs/flow --budget_pflop 2.5 --budget_min 25 --batch 64
#   (same for --model ddpm|gan|vae; --cond --run runs/flow_cond for the conditional model; add --resume to continue)
../bin/gpu_run ../.venv/bin/python evaluate.py main runs/vae runs/gan runs/ddpm runs/flow       # -> results/main_eval.json
../bin/gpu_run ../.venv/bin/python evaluate.py sweep runs/flow runs/ddpm runs/vae runs/gan      # -> results/sweep.json
../bin/gpu_run ../.venv/bin/python evaluate.py stability runs/vae runs/gan runs/ddpm runs/flow  # -> results/stability.json
../bin/gpu_run ../.venv/bin/python eval_cond.py runs/flow_cond                                   # -> results/cond_eval.json

# go-deeper: 2x budget = continue each final state: extend_budget.py runs/<m> runs/<m>_x2 --pflop 5 --minutes 50 (80 for U-Nets), train with --resume, then
../bin/gpu_run ../.venv/bin/python evaluate.py main_x2 runs/vae_x2 runs/gan_x2 runs/ddpm_x2 runs/flow_x2   # results/main_eval_x2.json
../bin/gpu_run ../.venv/bin/python evaluate.py sweep_x2 runs/flow_x2 runs/ddpm_x2                         # results/sweep_x2.json
# seed replicas (variance check)
../bin/gpu_run ../.venv/bin/python train_gen.py --model flow --run runs/flow_seed1 --seed 1 --budget_pflop 2.5 --budget_min 40 --batch 64 --n_ckpts 0

# demo media (CPU, plus a few seconds of sampling for the trajectory GIF)
../.venv/bin/python make_figures.py      # media/*.png, *.gif
../.venv/bin/python build_demo.py        # media/demo.html (self-contained, ~14 MB, open in any browser offline)
```

## File layout
```
data.py              procedural monster renderer + dataset builder + grid helper
models.py            AttrClassifier, VAE, DCGAN G/D, U-Net, analytic FLOP counter
train_classifier.py  evaluator training (held-out test accuracy -> results/classifier_32.json)
train_gen.py         one trainer for vae|gan|ddpm|flow (+--cond): matched budget caps, EMA, snapshots,
                     milestone checkpoints, bit-exact checkpoint/resume; also the samplers
extend_budget.py     clone a finished run into a continuation dir with a bigger budget (go-deeper 2x runs)
session.py           work queue run inside one gpu_run slot (task list, locks, resume); queue.sh re-queues it
evaluate.py          metrics (valid, attr TV, coverage, CFD, precision/recall, diversity, memorization), sweeps
eval_cond.py         attribute accuracy of the conditional model over all 1296 combos x guidance scales
make_figures.py      grids, training GIF, trajectory GIF, comparison table, quality-latency, stability, memorization
build_demo.py        media/demo.html "Monster Factory" gallery (baked samples, base64-embedded)
smoke.sh             end-to-end smoke check
runs/<model>/        config.json, snaps/*.png (fixed-noise progress grids), ckpt_1..3/, final/, latest/,
                     samples_final.npz (5000 eval samples + NN indices)
checkpoints/         classifier_32.safetensors + <model>/{ema.safetensors,config.json,meta.json} for vae, gan, ddpm, flow,
                     flow_cond and the 2x-budget *_x2 models (the EMA weights behind every sample/demo). Full training state (weights, EMA,
                     optimizer, RNG, step/budget counters) lives in runs/<model>/{latest,final,ckpt_1..3}/
results/             *.json metrics
media/               demo.html, sample_grids.png, training_progress.gif, trajectory.gif, comparison_table.png, ...
logs/                training/eval logs
```

**What ships and what doesn't.** The repo-root `.gitignore` excludes `data/` and the **whole** `runs/` tree (`**/runs/`), so a clone has none of `runs/` (no training state, no `snaps/`, no `samples_final.npz`, no `combos.npz`). What ships is `checkpoints/<model>/` (EMA weights, config and the training `meta.json` log), `results/*.json`, `media/` (incl. the built `demo.html`) and `logs/`. On a clean clone:
- **Works directly:** `load_generator("checkpoints/<m>")` or `load_generator("runs/<m>")` (falls back to `checkpoints/<m>`), sampling, and `evaluate.py main|main_x2|sweep|sweep_x2 runs/<m> ...` after `data.py` rebuilds the dataset (classifier is in `checkpoints/`). `evaluate.py main` also rewrites `runs/<m>/samples_final.npz`, which `make_figures.py` and `build_demo.py` read.
- **Needs retraining (not reproducible from the clone):** `evaluate.py stability` (milestone checkpoints `runs/<m>/ckpt_*` are not committed), the training-progress GIF (`runs/<m>/snaps`) and `make_figures.py loss` (reads `runs/<m>/final/meta.json`; a copy of each log is in `checkpoints/<m>/meta.json`). The rendered versions are in `media/`. `eval_cond.py runs/flow_cond` works from `checkpoints/flow_cond` and regenerates `runs/flow_cond/combos.npz` for the demo's order-a-monster section.

To reload a generator checkpoint in your own script:
```python
import train_gen as TG, mlx.core as mx
model, g, cfg = TG.load_generator("checkpoints/flow")     # or "runs/flow" (uses runs/flow/final)
x = TG.sample(model, g, 64, cfg, mx.random.key(0), steps=32)   # (64,32,32,3) in [-1,1]
```
