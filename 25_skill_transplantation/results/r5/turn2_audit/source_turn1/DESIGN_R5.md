# Round 5: add skills without erasing old ones

**Hypotheses.** Routing frozen-trunk rank-8 adapters will preserve old policy parameters but may lack capacity for a new gait; replay DAgger will acquire more smoothly but can forget; cumulative joint PPO may equal either once teacher work is charged. Good isolated skills may still fail on switches. No hypothesis requires a positive result.

**Task and methods.** HalfCheetah-v5, additions **forward → backward → slow cruise**, target velocities **+3, −3, +1 m/s**. All use the same 17 observations, task label, fixed physical input scaling, and action bounds. Reward is `exp(-0.5*(v-target)^2) - 0.03*sum(action²)`; this deliberately changes the old unbounded rewards, so old return numbers are not comparable. Train a fresh shared 20→128→128 actor/critic on forward for 262,144 steps. No earlier checkpoint or fitted normalizer is reused. From that identical start: (1) freeze the base and each completed route; train low-rank deltas and biases on all actor/critic layers for each new skill, (2) sequential DAgger with 8,192 FIFO examples per task, balanced replay minibatches, new student-state queries of every seen skill, and independently trained PPO teachers, (3) **cumulative joint PPO on all currently available skills**, continuing the shared model at each addition; the final stage trains all three. It is not a future-informed all-three-from-start upper bound. Include teacher routing and zero-action diagnostics.

**Baseline tuning.** Fresh CPG per task: frequency 0.5–8 Hz, amplitudes 0–2, phases ±π, biases ±1, actions clipped. Each task gets equal CEM search: 2 restarts × 32 generations × 16 candidates × 500 steps = **512,000 planned search steps/task**, plus validation. Select each restart's champion/final mean on three validation seeds, then select continuous versus reset phase on validation switch episodes. Record box-edge diagnostics and all search cost. Learned rank/LR are fixed, with no test-driven search; the baseline gets a deliberately generous independent search budget. A rising curve or boundary hit warrants an explicitly labelled later validation-only extension, not a claim of optimal CPG tuning.

**Evaluation and metrics.** Fresh test bank 7,000,000+ (four resets per training seed), disjoint train/CPG/val banks; old 10,000–10,001 resets are secondary. Isolated episodes: 600 steps; transitions: all six permutations, 200 steps/command, **no reset at switches**. Evaluate each learned acquisition snapshot on all seen skills. Report raw return, velocity MAE, target-band occupancy (±0.5 m/s), occupancy loss/ratio from acquisition (ratio unqualified below 5% acquisition), falls (height <0.3 m or wrapped pitch >1.2 rad for five steps), stalls (|v|<0.1 for 20 steps after a 10-step grace), and time to ten consecutive in-band steps. Non-settlers receive the full 10-second segment penalty; switching failure is fall/stall/non-settlement. Always act: 100% command coverage. Fall is a proxy, not native termination. Report actor bytes/count, full checkpoint bytes, trainable counts, env/teacher/gradient examples and wall time. Save each method's worst test transition for offline animation; qualification requires acquiring the new skill, not just retaining a weak old policy.

**Budget and minimum viable version.** Battery-first: one seed, all three skills/methods and both baseline/diagnostics; training guard 25 min, CPG 5, evaluation 2, reload 0.5, smoke ≤2 (**≤34.5 min planned limits**, queue time excluded). Each addition has **524,288 exact training credits**: one env step or one teacher query example. DAgger spends 393,216 teacher-training steps + 65,536 student steps + 65,536 queries; adapter/joint spend 524,288 PPO steps. Base is charged once to every arm: 1,310,720 credits each at stage 3. Teacher optimizer work is included in each ledger. Credits are an explicit acquisition-cost convention, **not equal FLOPs or seconds**; all compute components remain visible. CPG and held-out eval are separately charged. One process, one BLAS thread, bounded replay; expected memory well below 16 GB, peak RSS not yet measured. Every run has `--max-minutes` and atomic resumable checkpoints; smoke kills/restarts a real process before the >20-minute run. On AC only, repeat identical budgets for seeds 1 and 2 (three chained jobs total, each <45 min). If guarded out, preserve partial checkpoints and report incomplete; do not shorten just one arm. Minimum viable result is one completed seed, no cross-seed generalization claim. All timing expectations and learning outcomes await Claude's runs.
